# V0.1 Authority Migration Ledger

> **Status:** complete and independently verified 2026-09-03  
> **Scope:** exhaustive audit of `spec_mvp_v0.1.md`, sections 0–18  
> **Normative consequence:** this ledger records where legacy material goes; it does not add a domain decision or authorize implementation.

## Authority and classification

The migration order is scoped by the kind of statement, not by which file happens to contain it:

| Authority | Owns | Does not own |
|---|---|---|
| `PROJECT_CONTEXT.md` | Product purpose, audience, physical organizing principle, durable product boundaries, and the six Research Line themes | Schema sketches, exact routes, implementation counts, or phase plans when delegated sources differ |
| `CONTEXT.md` | Canonical domain language and category boundaries | The executable file layout or build command contract |
| `docs/adr/*.md` | Durable trade-offs and frozen vocabulary/governance choices | A complete implementation plan |
| `V0.1_EXECUTION_SPEC.md` | The executable five-Work V0.1 contract, gates, routes, validation, rendering, and CI boundary | Product intent outside its V0.1 scope |
| `.planning/*` | Derived implementation planning after this migration is complete | Independent requirements or new domain decisions |
| `paper_graph_investigation_v0.1.md` | Non-normative investigation evidence and rationale | Requirements, schema authority, or release criteria |

The legacy spec is therefore not allowed to compete with the sources above. `spec_mvp_v0.1.md` is marked **Superseded** and links here and to `V0.1_EXECUTION_SPEC.md`. The investigation document remains available as evidence and is not promoted to authority.

The three migration classes are:

- **A — already decided but not migrated:** retain the requirement, with the final destination named below. It must be represented by the authoritative source or its derived planning artifact, not copied as an independent legacy rule.
- **B — superseded legacy requirement:** do not carry the legacy wording forward. The replacing authority is named below.
- **C — genuinely new decision:** the authoritative documents cannot resolve the requirement. This class would reopen the decision frontier and requires a new user decision.
